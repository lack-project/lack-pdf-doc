# AI Usage Info

## Sinn der Library

PHP-8.5-Convenience-Layer über `tecnickcom/tc-lib-pdf`. Neben `SimpleDocument` und der Letter-spezifischen API steht mit `TemplateDocument` eine generische Pipeline für Front-Matter-basierte HTML-Templates zur Verfügung.

## Aktuelle öffentliche API

- `Lack\PdfDoc\SimpleDocument`: neutrales Markdown-/HTML-Dokument mit `toPdf()`.
- `Lack\PdfDoc\Template\TemplateDocument`: generisches Dokument aus HTML-Template, YAML-Front-Matter und Markdown-Inhalt.
- `Lack\PdfDoc\Template\TemplateContext`: Zugriff auf Metadaten und Config in registrierten `render:`-Callbacks.
- `Lack\PdfDoc\Letter\LetterConfig`: wiederverwendbare Briefpapier-Konfiguration mit `fromFile()` und `fromArray()`.
- `Lack\PdfDoc\Letter\LetterDocument`: konkrete Brief-API; bleibt parallel zur generischen Template-Pipeline bestehen.
- `Lack\PdfDoc\Form\InteractiveForm`: ausfüllbare Text-, Checkbox-, Auswahl- und digitale Signaturfelder über `document->form()`.
- `Lack\PdfDoc\Resource\ImageSource`: Bilddaten aus Bytes, Data-URL oder Callback.
- `Lack\PdfDoc\Resource\FontSource`: Alias auf isoliert nutzbare PDF-Core-Fonts.

## TemplateDocument

`TemplateDocument::fromTemplateFile()` lädt ein HTML-Template mit optionalem YAML-Front-Matter. Die Ladeschicht trennt Header und Body selbst und dekodiert YAML mit `phore_yaml_decode()`. `fromMarkdownFile()` verwendet dieselbe Struktur für Dokumentmetadaten und Markdown-Body. Dateien ohne Front Matter sind ebenfalls zulässig.

```php
$document = TemplateDocument::fromTemplateFile(
    __DIR__ . '/letter.template.html',
    safe: true,
)->fromMarkdownFile(__DIR__ . '/letter.md');

$pdf = $document->toPdf();
```

Templates können über `extends: file://...` voneinander erben. `{{ template }}` nimmt den Child-Template-Body auf; `{{ content }}` den gerenderten Markdown-Hauptinhalt.

Merge-Reihenfolge:

1. Defaults des ältesten Parent-Templates,
2. Defaults/Config der Child-Templates,
3. Front Matter des konkreten Markdown-Dokuments,
4. programmatische `metadataOverrides` / `configOverrides`.

Platzhalter:

- `{{ meta.* }}` — escaped Metadaten.
- `{{ markdown:meta.* }}` — Markdown aus Metadaten.
- `{{ image:meta.* }}` — Bildressource aus Metadaten.
- `{{ template }}` — Body des erbenden Child-Templates.
- `{{ content }}` — Markdown-Hauptinhalt des konkreten Dokuments.
- `{{ render:name }}` — registrierter Renderer-Callback für komplexes HTML.

Für komplexes HTML wird ein Renderer registriert:

```php
$document->renderer('candidateTable', function (TemplateContext $context): string {
    $candidate = $context->meta('candidate');
    return '<strong>' . htmlspecialchars($candidate['lastName'], ENT_QUOTES) . '</strong>';
});
```

## Config-Dateien und Ressourcen

`TemplateDocument::fromTemplateFile()` verwendet standardmäßig `safe: false`. In diesem Modus werden relative `file://`-Referenzen nicht automatisch geöffnet.

Mit `safe: true` können Parent-Templates und Bildressourcen relativ zur jeweils referenzierenden Datei aufgelöst werden. `file://assets/logo.png` ist relativ, `file:///opt/company/logo.png` absolut. Data-URLs können direkt verwendet werden. Font-Aliase werden z. B. als `body: builtin://helvetica` gesetzt.

Dateifehler aus `fromTemplateFile()` und `fromMarkdownFile()` nennen den betroffenen Dateipfad in der Exception. Der Aufrufer muss deshalb Existenz-/Lesbarkeitschecks nicht nochmals um diese Methoden herum bauen.

## Formulare und Signaturen

`document->form()` erzeugt AcroForm-Felder. `signature()` erzeugt ein echtes digitales PDF-Signaturfeld (`/FT /Sig`). Freihändige Maus-/Finger-Unterschriften bleiben Viewer-Funktion.

## Ressourcen-Sicherheit

tc-lib-pdf erhält keine freigegebenen Hosts oder Dokumentpfade. Relative Ressourcen aus Templates werden nur bei explizitem `safe: true` durch die Ladeschicht gelesen und anschließend in interne Ressourcen überführt; der Renderer selbst bleibt vom Dateisystem und Netzwerk isoliert.
