# AI Usage Info

## Sinn der Library

PHP-8.5-Convenience-Layer über `tecnickcom/tc-lib-pdf`. Neben `SimpleDocument` und der Letter-spezifischen API steht eine Front-Matter-basierte Pipeline für Dokumente, Templates und Fragmente zur Verfügung.

## Aktuelle öffentliche API

- `Lack\PdfDoc\Template\Document`: konkrete Dokumentinstanz. `Document::fromFile()` lädt `type: document`; `metadata()` und `markdown()` setzen beziehungsweise überschreiben die konkreten Daten und den Hauptinhalt; `template()` liefert das zugrunde liegende `TemplateDocument`.
- `Lack\PdfDoc\Template\TemplateDocument`: wiederverwendbare Dokumentvorlage. `TemplateDocument::fromFile()` lädt `type: template`; `createDocument()` erzeugt ein neues leeres `Document` auf Basis dieser Vorlage.
- `Lack\PdfDoc\Template\Fragment`: wiederverwendbarer Inhaltsbaustein. `Fragment::fromFile()` lädt ausschließlich `type: fragment`.
- `Lack\PdfDoc\Template\TemplateContext`: Zugriff auf Metadaten und Config eines konkreten `Document` in registrierten `render:`-Callbacks.
- `Lack\PdfDoc\SimpleDocument`: neutrales Markdown-/HTML-Dokument mit `toPdf()`.
- `Lack\PdfDoc\Letter\LetterDocument`: bestehende konkrete Brief-API; bleibt parallel zur generischen Template-Pipeline bestehen.

## Dateitypen und Ladewege

Das Dateimodell bildet die PHP-Typen direkt ab:

- `type: document` → `Document::fromFile()`
- `type: template` → `TemplateDocument::fromFile()`
- `type: fragment` → `Fragment::fromFile()`

Ein komplettes Dokument wird direkt geladen:

```php
$document = Document::fromFile(
    __DIR__ . '/letter.md',
    safe: true,
);

$document->metadata(['showTerms' => true]);
$pdf = $document->toPdf();
```

Ein Template kann unabhängig geladen und mehrfach verwendet werden:

```php
$template = TemplateDocument::fromFile(
    __DIR__ . '/invoice.template.html',
    safe: true,
);

$invoice = $template->createDocument()
    ->metadata($invoiceData)
    ->markdown($optionalMainContent);

$pdf = $invoice->toPdf();
```

`Document::template()` liefert wieder dasselbe Template-Objekt. Dadurch bleibt die Abhängigkeit eindeutig: `Document -> TemplateDocument -> Fragment`.

Der ältere Einstieg `TemplateDocument::fromTemplateFile(...)->fromMarkdownFile(...)` bleibt für bestehende Aufrufer kompatibel; für neue Implementierungen ist die typisierte `fromFile()`-API vorgesehen.

## Dokumentdatei

Eine konkrete `.md`-Datei enthält nur Typ, Template-Verweis, Daten und optionalen Hauptinhalt:

```yaml
---
type: document
template: file://letter.template.html
recipient:
  name: Erika Mustermann
showTerms: false
---

# Betreff

Normaler Dokumentinhalt.
```

## Template und Content-Bereich

Ein Template definiert Aufbau, Defaults, Haupt-Content-Bereiche und Fragmente:

```yaml
---
type: template
content:
  first:
    x: 20mm
    y: 82mm
    width: 170mm
    bottom: 34mm
  following:
    x: 20mm
    y: 24mm
    width: 170mm
    bottom: 15mm
fragments:
  - file://fragments/letterhead-first.md
  - file://fragments/logo-following.md
  - file://fragments/footer-first.md
  - file://fragments/terms.md
---
{{ content }}
```

Die `following`-Box ist der normale automatische Seitenfluss. Die kleinere `first`-Box wird auf Seite 1 über page-spezifische No-Write-Regions reserviert; Folgeseiten nutzen anschließend den größeren Standardbereich.

## Fragmente

Ein positioniertes Fragment verwendet `pages: first|following|all` sowie `position` mit `x`, `y`, `width`, `height`. Der Renderer setzt es als begrenzte `getHTMLCell()`-Box auf die ausgewählten Seiten. Ein Fragment ohne `position` kann mit `placement: after` an den Hauptinhalt angehängt werden. `if: meta.showTerms` aktiviert es nur bei einem finalen booleschen `true`.

Platzhalter:

- `{{ meta.* }}` — escaped Metadaten.
- `{{ markdown:meta.* }}` — Markdown aus Metadaten.
- `{{ image:meta.* }}` — Bildressource aus Metadaten.
- `{{ template }}` — Body des erbenden Child-Templates.
- `{{ content }}` — Markdown-Hauptinhalt des konkreten Dokuments.
- `{{ render:name }}` — registrierter Renderer-Callback für komplexes HTML.

Ausführliche Beispiele:

- [`examples/templates/04-letter-page-fragments.php`](examples/templates/04-letter-page-fragments.php) — komplettes Dokument mit `Document::fromFile()`.
- [`examples/templates/05-invoice-page-fragments.php`](examples/templates/05-invoice-page-fragments.php) — Template mit `TemplateDocument::fromFile()` laden und per `createDocument()` programmatisch befüllen.

## Layout und Ressourcen

`config.layout` kann weiterhin `pageLeft`, `pageRight`, `pageTop`, `pageBottom`, `bodyFont`, `bodyFontSize` und `bodyLineHeight` setzen. Sobald ein `content:`-Layout vorhanden ist, bestimmt dessen `following`-Box die normalen PDF-Seitenränder und die `first`-Box reserviert den abweichenden Bereich der ersten Seite.

`Document::fromFile()` und `TemplateDocument::fromFile()` verwenden standardmäßig `safe: false`. Relative `file://`-Verweise für Template-Referenzen, Vererbung, Fragmente und Bilder werden nur mit explizitem `safe: true` geöffnet und relativ zur referenzierenden Datei aufgelöst.

Dateifehler aus `fromFile()` nennen den tatsächlich verwendeten Dateipfad in der Exception. Der Aufrufer muss Existenz- oder Lesbarkeitsprüfungen deshalb nicht nochmals vor den Ladeaufruf setzen.

## Formulare und Signaturen

`document->form()` erzeugt AcroForm-Felder. `signature()` erzeugt ein echtes digitales PDF-Signaturfeld (`/FT /Sig`). Freihändige Maus-/Finger-Unterschriften bleiben Viewer-Funktion.

## Ressourcen-Sicherheit

tc-lib-pdf erhält keine freigegebenen Hosts oder Dokumentpfade. Relative Ressourcen aus vertrauenswürdigen Templates werden nur bei explizitem `safe: true` durch die Ladeschicht gelesen und anschließend in interne Ressourcen überführt; der Renderer selbst bleibt vom Netzwerk isoliert.
